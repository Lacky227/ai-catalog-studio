# AI Catalog Studio

Навчальна самостійна робота №2 — автоматизоване створення контенту інтернет-магазину. Українська адмінка, локальний Ollama, дворівневий каталог L1/L2 та статична вітрина. Модель не навчається заново: використовується готова Qwen3 4B Instruct.

## Запуск локально

Потрібні Python 3.10+ і Ollama. Модель `qwen3:4b-instruct` вже може бути встановлена. Перевір `ollama list`. За потреби запусти `ollama serve` в окремому терміналі (якщо працює системний сервіс, другий запуск не потрібен).

Linux:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Адмінка: http://127.0.0.1:8000/ ; магазин: http://127.0.0.1:8000/shop/ . Не відкривай адмінку в інтернет: вона призначена для локальної навчальної демонстрації, без авторизації. Налаштування моделі: `OLLAMA_MODEL`, `OLLAMA_URL` (необов'язкові змінні середовища).

## Робочий сценарій

1. В адмінці натисни «Приклад» або завантаж `sample-products.json`. Натисни «Імпортувати список» (до 20 товарів).
2. Натисни «Створити каталог через AI». Дочекайся JSON від моделі, перевір L1/L2. Повторна генерація каталогу скидає чернетки карток.
3. Натисни «Згенерувати всі відсутні картки» або «Генерувати» для окремого товару. Для кожного товару відбувається окремий запит Ollama; якщо виникла помилка, уже створені картки зберігаються. Можна повторно запустити генерацію відсутніх карток.
4. Для кожної картки натисни «Редагувати», перевір факти, виправ JSON, якщо потрібно, натисни «Зберегти зміни», потім «Підтвердити збережену версію».
5. Натисни «Опублікувати підтверджені». Файл `site/catalog.json` оновиться. Відкрий магазин, перевір каталог, пошук, деталі товару. Ціни й характеристики взято з імпортованих даних, ШІ генерує тексти та категорії; приклади відгуків явно позначено як демонстраційні. Реальних купівель або відгуків немає.

## Google Colab (хмарна демонстрація)

Відкрий `notebooks/cloud_generation.ipynb` у Google Colab, за можливості обери GPU, завантаж ZIP проєкту у першій комірці. Ноутбук встановлює Ollama та завантажує ту саму модель у хмарне середовище, генерує каталог і картки тим самим `engine.py`. Перевір результати; після перевірки зміни `APPROVE = False` на `True` та виконай останню комірку. Завантажений `catalog.json` можна покласти у локальну папку `site/` замість наявного. Це окремий хмарний режим; локальна адмінка напряму не звертається до Colab. Потрібен доступ Colab до інтернету і достатні ресурси. Реальний запуск Colab не перевірено тут. Модель готова, а не навчена з нуля; якщо викладач вимагає власноруч навчену модель, узгодь використання готової моделі.

## GitHub та CI/CD

Створи **новий порожній публічний** репозиторій `ai-catalog-studio`, без README, додай співучасника через Settings → Collaborators. Після генерації та публікації контенту локально виконай:

```bash
git init
git add .
git commit -m "Initial commit: AI Catalog Studio"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/ai-catalog-studio.git
git push -u origin main
```

Settings → Pages → Source → GitHub Actions. Якщо перший workflow не пройшов через неактивні Pages, після активації повтори запуск Actions → Re-run all jobs. Вітрина публікується з `site/` через `.github/workflows/pages.yml`. GitHub Pages не запускає Python або Ollama; він публікує лише перевірений статичний каталог. Щоб оновити сайт, після локальної публікації або експорту з Colab закоміть `site/catalog.json` і виконай `git push`. CI тестує контракти та API з підставною відповіддю моделі, а не запускає реальний Ollama.

Командна робота: партнер клонує репозиторій, створює гілку `docs/improve-readme`, змінює README, робить commit/push і створює Pull Request у main. Перевір PR, об'єднай після зеленого тесту. Deployment запускається тільки для main, тестування також для PR.
